# 量化指标实现方案

本项目的 workflow 指标由 `principia_ai.metrics` 模块统一收集，并在 `run_workflow.py`、`run_batch_workflow.py` 和端到端 benchmark 中落盘。指标用于判断 agent 链路是否稳定、token 消耗是否异常，以及执行结果是否通过校验。

## 采集入口

- `MetricsTracker`: 单例指标追踪器，记录任务 ID、用户请求、起止时间、agent 执行次数、agent 耗时、token 消耗、任务事件、验证结果和错误。
- `track_agent_execution`: agent 方法装饰器，自动记录执行次数、耗时和异常。
- `TokenTrackingCallbackHandler`: LangChain/LangGraph callback，读取 LLM 返回的 token usage 并写入 tracker。
- `MetricsReporter`: 将指标保存为 JSON 和文本摘要，默认写入 case 同级的 `metrics_reports/` 目录或 batch 输出目录。

## 核心指标

- **运行耗时**: `start_time`、`end_time` 和总执行时间。
- **Token 消耗**: 总输入、总输出、总 token，以及按 agent 聚合的 token 分布。
- **Agent 执行**: 每个 agent 的执行次数、平均耗时、最小/最大耗时和错误次数。
- **任务状态**: planned、completed、failed、retried 计数。
- **验证结果**: reviewer 或 workflow guard 记录的通过/失败次数。
- **错误记录**: agent 名称、时间戳和截断后的错误摘要。

## 输出文件

单次 workflow 结束后，`MetricsReporter.save_report()` 会生成：

```text
metrics_<task_id>_<timestamp>.json
report_<task_id>_<timestamp>.txt
```

JSON 文件适合后续统计，文本文件适合快速人工检查。端到端 benchmark 会额外汇总 workflow 退出码、超时状态、执行状态文件、求解器日志是否 clean end、报告文件是否存在等黑盒指标。

## 使用建议

1. 单次调试时先看文本报告，确认耗时、token 和错误集中在哪个 agent。
2. 批量实验时优先分析 JSON，按 `tokens_by_agent`、`agent_timings` 和 `validation_results` 聚合。
3. 若 execution 相关指标异常，应同时检查 `execution_status.json`、`execution_report.md` 和 solver log。
4. 指标文件不得包含 `.env` 内容；日志和 diff 输出会经过敏感信息脱敏。
